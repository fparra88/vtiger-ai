# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Vtiger CRM 8.4.0 (PHP >= 8.1, MySQL, Smarty 4, Apache) — a large legacy PHP monolith, plus local custom additions (AI Assistant, WhatsApp Notifier, Docker setup). There is no build step, linter, or automated test suite; changes are verified by running the app. The `test/` directory is runtime storage (uploads, templates_c, etc.), not unit tests.

## Running it

- Docker (the supported local path): `docker compose up --build` → app on http://localhost:8080/, MySQL 8 in the `db` service. Image is `php:8.3-apache` with mysqli/imap/gd/zip/opcache; `composer install` runs in a build stage (`vendor/` is baked into the image).
- Dependencies without Docker: `composer install` (see [install-composer-deps.sh](install-composer-deps.sh)).
- Config layering: [config.php](config.php) includes `config.inc.php` (generated by the installer; holds `$dbconfig`, `$site_URL`, `$root_directory`, `$application_unique_key`), then [config_override.php](config_override.php), which overrides those from env vars (`DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`, `SITE_URL`, `ROOT_DIRECTORY`, `APPLICATION_UNIQUE_KEY`) when set. Other `config.*.php` files (performance, security, csrf-secret, db) are split-out settings. Prefer editing overrides over the installer-generated `config.inc.php`.
- Cron: [vtigercron.php](vtigercron.php) is the scheduler entry point; it runs `cron/modules/**/*.service` handlers (each self-bootstraps `PearDatabase`, etc.). On Windows use [run_vtigercron.bat](run_vtigercron.bat) / `run_vtigercron_hidden.vbs`.
- Ad-hoc CLI scripts at repo root (`test_openai_cli.php`, `test_whatsapp_cli.php`, `test_ai_personalize_cli.php`) are throwaway manual checks, e.g. `php test_whatsapp_cli.php <toNumber> [templateName]`. `setup_*.php` / `register_whatsapp_task.php` are one-shot DB/schema setup scripts for the custom modules (add columns, register cron tasks) — run once per environment.

## Architecture

**Request flow.** [index.php](index.php) → `includes/` (Loader, runtime, `includes/main/WebUI.php`) → a module's `views/*` (renders) or `actions/*` (JSON/side effects), selected by `?module=X&view=Y` / `&action=Z` (parent `&parent=Settings` for admin screens). Class names encode the path and are autoloaded by `includes/Loader.php`: `Accounts_Detail_View` → `modules/Accounts/views/Detail.php`; `Settings_Webforms_List_View` → `modules/Settings/Webforms/views/List.php`; models use `_Model` (`Vtiger_Record_Model`), actions `_Action`, views `_View`. Modules fall back to the `Vtiger` module classes when they don't define their own, so look in `modules/Vtiger/{views,actions,models,uitypes,handlers}` for defaults.

**Two data-access layers coexist.**
- Legacy `CRMEntity` subclasses (`modules/<Module>/<Module>.php`, base in [modules/Vtiger/CRMEntity.php](modules/Vtiger/CRMEntity.php)) own table/column metadata and save logic; DB access via `PearDatabase` (`include/database/PearDatabase.php`, ADOdb-style `pquery()` with `?` placeholders — use prepared queries).
- Model layer (`Vtiger_Record_Model`, `Vtiger_Module_Model`, `Vtiger_Field_Model`) built on top, used by the UI.
- `vtlib/` is the module-management API (create modules/fields/blocks/links programmatically; used by installers and by the `setup_*.php` scripts). `schema/` + each module's `schema.xml` describe DB tables.

**Generated/cached metadata.** [tabdata.php](tabdata.php), [parent_tabdata.php](parent_tabdata.php) and `user_privileges/*` are generated files (tab ids, per-user role/sharing privileges). They are regenerated by vtiger (e.g. when modules are installed or roles change) — don't hand-edit; they show up as modified in git. Smarty compiled templates go to `test/templates_c`; `cache/` and `storage/` hold runtime data.

**Front end.** `layouts/vlayout` (legacy UI, what this install uses — most local template edits live here) and `layouts/v7`. Per-module Smarty templates live in `layouts/<layout>/modules/<Module>/*.tpl` with sibling `resources/*.js` (jQuery-based, class-style `Vtiger_*_Js`). A module can override Vtiger's default template/JS by providing the same filename under its own directory. Language strings: `languages/<locale>/<Module>.php` (`$languageStrings`, `$jsLanguageStrings`); this install primarily uses `en_us`. After changing templates, clear `test/templates_c` if stale output appears.

**Web services.** [webservice.php](webservice.php) + `include/Webservices/` expose the REST/ws API used by the mobile and customer portal clients; `modules/CustomerPortal`, `modules/Mobile`, `modules/Portal` back those.

**Workflows & handlers.** `modules/com_vtiger_workflow` implements Settings > Workflows (tasks run on save events and via cron). Per-module event handlers live in `modules/<Module>/handlers/` and are registered through `vtlib` `EventsManager`.

## Local custom modules (not upstream Vtiger)

- `modules/AIAssistant` — OpenAI-backed chat/search/reports assistant (`providers/OpenAIProvider.php`, `CrmSearch.php`, `CrmReports.php`; `actions/Chat.php`, `Permission.php`). Configured under Settings > AI Assistant; also does Lead/HelpDesk scoring via cron (`cron/modules/AIAssistant/aiassistant.service`), writing `ai_score` / `ai_score_reason` columns added by `setup_ai_scoring_fields.php`. `setup_ai_chat_links.php` registers the chat UI links.
- `modules/WhatsAppNotifier` — Meta Cloud API integration (`providers/MetaCloudAPIProvider.php`, webhook in `callbacks/MetaWebhook.php`, setup in `WhatsAppNotifierSetup.php`, cron jobs in `cron/modules/WhatsAppNotifier/*.service` registered via `setup_whatsapp_cron_jobs.php` / `CronJobConfig.php`).
- Local edits also exist in the Project, Services, CustomerPortal, SMSNotifier and Webforms layouts (see `git status`).

## Conventions

- Upstream commit style is `Fixes #NNNN: <short description>`.
- Keep security hygiene consistent with recent upstream fixes: sanitize user input before output/headers, use `pquery` placeholders, validate column/field info before use in filters/reports.
- Many generated/runtime paths (`cache/`, `logs/`, `storage/`, `test/`, `user_privileges/`, `tabdata.php`) change at runtime — avoid committing incidental changes to them.
